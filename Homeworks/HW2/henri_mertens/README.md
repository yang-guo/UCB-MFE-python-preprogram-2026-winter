The pipeline cleans the supplied equity data, creates a parameterized single-stock
risk report, and runs the same analysis over every cleaned ticker. All code and
outputs belong to this homework directory; course lecture files are unchanged.

## Files and run order

1. `01_data_cleaning.ipynb`: inspect `ohlc_hw`, preserve the diagnosis, repair or
   quarantine invalid observations, and recreate `ohlc_hw_cleaned`.
2. `02_stock_report_template.ipynb`: a Papermill template with a genuinely tagged
   `parameters` cell, four charts, ten summary statistics and named Scrapbook results.
3. `03_run_all_stocks.py`: execute the template for every cleaned ticker, isolate
   failures, collect this run's successful reports and create the summary dashboard.
4. `requirements.txt`: pinned dependencies from the tested local environment.

## Setup and execution

Tested on Windows with Python 3.12.9. These PowerShell commands use `uv`.
Run from **this homework directory**. Put a local copy of the instructor's database
at `data/data.db`; it must contain `ohlc_hw` and the supplied `ohlc` reference.
The database is intentionally excluded from Git.

```powershell
uv venv --python 3.12.9 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name python3 --display-name "HW2 Python"
```

The kernel installation above is confined to the virtual environment.
If the environment already exists, reuse it rather than recreating it.

Execute cleaning first. Its executed copy goes into the ignored environment:

```powershell
.\.venv\Scripts\papermill.exe 01_data_cleaning.ipynb .venv/cleaning_executed.ipynb --kernel python3 --cwd .
```

An individual report can be generated by changing the template's parameters,
or by passing them explicitly:

```powershell
.\.venv\Scripts\papermill.exe 02_stock_report_template.ipynb .venv/AAPL_example.ipynb --kernel python3 --cwd . -p ticker AAPL -p start_date 2024-06-01 -p end_date 2024-11-30
```

Run the entire universe:

```powershell
.\.venv\Scripts\python.exe 03_run_all_stocks.py --kernel python3
```

`--db`, `--template` and `--output-root` accept alternative paths. Defaults are
anchored to the script's directory. Select a different installed kernel with
`--kernel`. `--run-date YYYY-MM-DD` controls only the output folder; the default
is the computer's local run date. It never changes the historical window.

The report notebook and batch use SQLite read-only connections. Only the cleaning
notebook writes, and only to the working copy's cleaned table. It checks source-table
fingerprints before and after writing.

## Cleaning decisions

- Normalize ticker HTML markup, whitespace and case before grouping and deduplicating.
  Preserve original labels and source-row identifiers.
- Remove identical normalized market records. Quarantine conflicting ticker/date
  records rather than selecting an arbitrary version.
- Compare dates with the supplied `ohlc` history **for each ticker**, not a weekday
  calendar that would misclassify exchange holidays.
- Drop all-missing raw OHLC rows before filling. Forward-fill other missing raw
  prices within a sorted ticker only. Treat invalid prices and out-of-range
  open/close values as suspect, then recheck every raw OHLC bound. Quarantine
  unresolved leading gaps, ambiguous inverted ranges and unsuccessful repairs.
- Missing volume becomes zero with a missing-volume repair flag. An original zero
  volume is a review flag, not proof of no trading or automatic grounds for deletion.
  Negative/non-finite volume is quarantined.
- Reconstruct missing/invalid adjusted close with the exact ticker/date's reference
  factor `reference adj_close / reference close`. Investigation also found positive
  adjusted closes about 4–24 times the reference convention; repair those with the
  same factors. After a raw-close repair, reapply that date's factor. Never carry
  factors across unverified corporate actions. Preserve original values, repair
  reasons and factors alongside retained rows.
- Flag both tails of the three-sample-standard-deviation screen (`ddof=1`) on simple
  raw-close returns. Every initially flagged close matches the supplied reference.
  Their economic causes are unverified: retain them with review flags rather than
  claiming they are established errors, splits or news events.
- Interpolate only documented confirmed close errors, between valid neighbors within
  a ticker and without endpoint extrapolation. Controlled fixtures demonstrate this;
  no real raw-close error was established in this snapshot.

The reference supports the assignment's adjustment convention and date coverage;
it is not an independent guarantee that every original observation is correct.
Raw OHLC bounds do not apply to adjusted close.

## Report metrics and charts

Reports use adjusted-close **log returns**, unlike the simple raw-close returns
used for the cleaning diagnostic.

- Rolling volatility is the 20-return sample standard deviation times `sqrt(252)`.
  It needs at least 21 prices. Gray price segments mark unavailable warm-up volatility;
  red/green segments are above/at-or-below mean rolling volatility. Coloring is retrospective.
- The moving average needs 50 prices within the report window. Warm-up gaps remain
  unavailable rather than being filled with zero.
- Drawdown is `adjusted_close / running_peak - 1`, using the peak inside the report
  window. Maximum drawdown is the minimum of this recoverable series.
- Sharpe uses the course approximation
  `(mean(log_returns) * 252 - 0.02) / (std(log_returns, ddof=1) * sqrt(252))`.
  Fewer than two returns or numerically zero volatility produces `N/A`.
- Total return is `last_adjusted_close / first_adjusted_close - 1`.
  Annualized return is `exp(sum(log_returns) * 252 / n_returns) - 1`.
  Whole-period annualized volatility uses all observed returns.
- Best/worst days and up/down averages use log returns. Positive-day percentage
  includes zero-return days in its denominator; empty up/down subsets display `N/A`.

The four panels show adjusted price/MA, signed returns, rolling volatility and
shaded drawdown with its worst point marked. Named Scrapbook output `report_metrics`
stores the exact metrics and actual coverage for batch collection.

## Batch window, outputs and limitations

Use the six calendar months **before the month containing the latest cleaned
observation**, even if that observation is month-end. December 6 or December 31,
2024 both produce June 1–November 30, 2024. The computer's current date does not enter
this calculation.

Each run writes to `reports/<run-date>/`:

- `<ticker>_report.ipynb`: executed report.
- `portfolio_summary.csv`: the seven required columns plus requested/actual
  coverage, price/return counts and coverage notes.
- `portfolio_risk_return.png`: mean rolling annualized volatility versus total
  return, colored by Sharpe, with the five highest plotted returns labeled.
- `failed_stocks.txt`: failures and tracebacks; empty when there are none.
- `run_manifest.json`: window, universe, successful report paths, failed tickers and state.

CSV `avg_volatility` is **mean rolling volatility**, distinct from whole-period
volatility. Returns and volatility remain fractions (0.10 means 10%). Undefined
metrics are blank CSV cells and excluded from Sharpe rankings. Top/bottom ten groups
may overlap with fewer than 20 defined Sharpe ratios.

Some supplied histories end October 18, 2024, while others extend into December.
Reports show actual dates and never extrapolate trailing gaps. A common requested
window does **not** guarantee identical actual coverage: rankings and scatter
comparisons need that context. This compares individual stocks, not a weighted
portfolio return.

Collect only successfully executed and validated reports from the current loop.
A folder scan cannot include stale/failed notebooks. An all-failed run writes failure
logs and no current CSV/chart. Same-day reruns replace this driver's summary/chart
and requested reports; unrelated old notebook files stay untouched and are not
collected. Any failed report gives a nonzero exit code after all tickers are attempted.
