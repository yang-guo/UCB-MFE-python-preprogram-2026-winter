## Which HW4 model is served, and why

- `model_version`: `hw4-ridge-ranks-20141231-v1`
- HW4's chosen strategy is an equal-weight average of four cross-sectional ranks and has no fitted parameters. In the same HW4 experiment, `Ridge(alpha=100.0, positive=True)` learned weights on exactly those four ranks, refit before each validation year (`model.fit_weights` and `model.walk_forward_scores`, results in HW4 `development.md`). That fitted comparison model is what this service serves.
- The served version is the 2014-12-31 fit, the last fit of the HW4 development comparison. It used the 59,183 monthly signals whose 90-day outcome ended before 2014-12-31 (last label end 2014-12-30), with training targets clipped to their 1% and 99% quantiles. Learned weight shares are 31% momentum, 0% 52-week high, 0% low volatility, 69% profitability, matching the HW4 record.
- HW4 did not save a model file, so `export_model.py` reproduces that fit offline from the HW4 code and database. It stops unless HW4's year-end rule selects 2014-12-31 and the training size and rounded weight shares match the audit values recorded in HW4 `development.md`. It then records one real HW4 signal (symbol A on 2014-12-31) with the score produced by HW4's own `walk_forward_scores`, serializes the bundle with joblib, reloads it, and checks that the reloaded prediction matches within 1e-12. The saved artifact is included, so running the service does not require re-exporting the model.
- HW4 sources at that commit: [model.py](https://github.com/yang-guo/UCB-MFE-python-preprogram-2026-winter/blob/80640fc73d63d8111cf9fb68fda270cf2240d8ac/Homeworks/HW4/Qianhao_Meng/model.py) (`add_ranks`, `fit_weights`, `walk_forward_scores`), [data.py](https://github.com/yang-guo/UCB-MFE-python-preprogram-2026-winter/blob/80640fc73d63d8111cf9fb68fda270cf2240d8ac/Homeworks/HW4/Qianhao_Meng/data.py) (panel and 90-day target), [development.md](https://github.com/yang-guo/UCB-MFE-python-preprogram-2026-winter/blob/80640fc73d63d8111cf9fb68fda270cf2240d8ac/Homeworks/HW4/Qianhao_Meng/development.md) (the fit record).
- Preprocessing: the Ridge was fitted directly on the four ranks. There is no fitted scaler or imputer, so there is no learned preprocessing to save, and the bundle holds only the fitted Ridge, the version and the feature names. The ranks are input features produced upstream by HW4's deterministic `add_ranks` rule, which needs the whole cross-section of eligible stocks on a date and has no fitted parameters. The 1% and 99% clipping was applied to training targets only. The thresholds are recorded in the metadata and nothing is clipped at inference.
- At startup the service loads `artifacts/model.joblib` once per server process and checks that its feature names match the input contract. Prediction requests use the saved estimator and never retrain or read the HW4 database. The artifact is a pickle, so only files built by `export_model.py` from a trusted checkout should be loaded.

## Input and output contract

`POST /predict` takes a JSON object with exactly these four fields. The order is the model's feature order.

| Field | Meaning | Type and range |
| --- | --- | --- |
| `rank_momentum_252_21` | Same-date percentile rank of 12-1 momentum (252-session return skipping the latest 21 sessions). Higher is stronger. | float in [0, 1] |
| `rank_drawdown_252` | Same-date percentile rank of closeness to the 252-session high. Higher is closer to the high. | float in [0, 1] |
| `rank_volatility_63` | Same-date percentile rank of 63-session volatility, reversed. Higher is calmer. | float in [0, 1] |
| `rank_operating_roa` | Same-date percentile rank of operating return on assets. Higher is more profitable. | float in [0, 1] |

- Ranks are unitless. They come from HW4 `model.add_ranks`, computed among all eligible stocks on the same signal date. A missing component is set to the neutral rank 0.5 upstream. One request describes one stock on one date. The service never computes ranks.
- Validation is strict. Every field is required and no other field is allowed. Values must be JSON numbers (a JSON integer 0 or 1 is accepted as a float). Numeric strings, booleans and null are rejected. NaN, Infinity and overflowing literals such as 1e309 are rejected. Values outside [0, 1] are rejected. Because the fields are named, a wrong feature count is a missing or extra field.
- `200`: `{"prediction": <finite float>, "model_version": "hw4-ridge-ranks-20141231-v1"}`. `prediction` is the expected gross adjusted-price return as a fraction over the HW4 horizon: entry at the close of the next session after the signal date, exit at the first quoted close on or after the entry date plus 90 calendar days, before fees. The model was trained on clipped targets. For this version, predictions over the valid input range are approximately 0.0371 (all ranks 0) to 0.0519 (all ranks 1). In HW4 the number served as a ranking score.
- `422`: any validation failure. The body lists `loc`, `msg` and `type` for each error and does not echo the raw input. The model is never called.
- `500`: an unexpected inference failure. The body is `{"detail": "Prediction unavailable"}` and the full exception goes to the server log with the `X-Request-ID` header value.

Example: `example_request.json` returns `prediction` 0.041160 for symbol A on 2014-12-31.

## Setup

Python 3.12 and a separate environment inside this folder. The pinned model libraries (scikit-learn 1.8.0, numpy 2.3.5, pandas 2.3.3, joblib 1.5.3) are the versions of the course `uv.lock` that HW4 trained with, so the template versions were kept.


## Reproduce

All commands run from this folder. The export command changes directory inside a subshell and returns here.

1. Export the model (optional, the artifact is committed). This needs the repository `.venv` from `uv sync --locked`, `Lectures/modeling/data/equities_top2000.duckdb` from bCourses, and the HW4 code at `Homeworks/HW4/Qianhao_Meng`. On a branch that does not contain HW4, restore it into the working tree first without staging it. It is the only step that reads the database. It stops with a message if the fit date, training size or weight shares differ from the HW4 record.

   ```sh
   ( cd ../../.. && git restore --source=80640fc7 --worktree -- Homeworks/HW4/Qianhao_Meng )
   ( cd ../../.. && .venv/bin/python Homeworks/HW5/Qianhao_Meng/export_model.py )
   ```

2. Lint and test. The performance test writes `latency_report.md`.

   ```sh
   make lint
   make test
   ```

3. Run locally without Docker. Stop it with Ctrl-C before step 4, because the container maps the same host port 8000.

   ```sh
   python -m uvicorn app:app --host 127.0.0.1 --port 8000
   ```

4. Build and run the container. `make run` keeps the terminal.

   ```sh
   make build
   make run
   ```

   From a second terminal in this folder, send a valid and an invalid request:

   ```sh
   curl -i http://127.0.0.1:8000/predict -H 'Content-Type: application/json' --data-binary @example_request.json
   curl -i http://127.0.0.1:8000/predict -H 'Content-Type: application/json' --data-binary '{"rank_momentum_252_21": "0.5", "rank_drawdown_252": 0.5, "rank_volatility_63": 0.5, "rank_operating_roa": 0.5}'
   ```

   To check the restart, stop the container with Ctrl-C, run `make run` again without rebuilding, and repeat the valid request.

## Tests

- Valid prediction: real artifact, status 200, response schema, `model_version`, agreement to within 1e-12 with a direct `predict` call on the saved estimator, made in the test on a DataFrame built in training column order without the service wrapper, and agreement with the reference recorded by `export_model.py` from HW4's scoring code to within 1e-9. The 1e-9 tolerance allows small floating-point differences between machines. The test also checks that `example_request.json` equals the recorded input.
- Input validation: 14 raw request bodies (missing field, extra field, list bodies, numeric string, boolean, null, out of range both ways, NaN, Infinity, -Infinity, 1e309, not JSON) all return 422 through the in-process `TestClient`. In every case `predict` is replaced by a function that fails the test if called.
- Inference failure: `predict` is replaced by a function that raises, valid input is sent, and the response is 500 without the exception text. The valid-prediction, performance and batch tests use the saved model unchanged.
- Performance: 5 warm-up requests, then 50 timed requests with `time.perf_counter` through the in-process `TestClient`, so no network hop. Median, p95, hardware and Python version are written to `latency_report.md` on every run. The committed `latency_report.md` is the one from the final `make test` on the author's MacBook Pro (Apple silicon, Python 3.12.14), where the median was about 1 ms. The asserted budget is a 50 ms median, a coarse regression threshold for a four-feature linear model on a laptop, far above the measured median.
- Extra: one row's prediction does not depend on other rows in the same batch, and `/health` reports the loaded version.

## Before a real deployment

- The ranks must be produced by the same code and universe as HW4 on each signal date. That pipeline is not part of this service and would need its own tests and monitoring.
- The model was fit on data through 2014. It would need an evaluation on recent completed outcomes and a retraining schedule before use.
- The service has no authentication, rate limiting, durable request logging or metrics export.
- Latency was measured in-process on one machine. A real deployment needs an HTTP-level measurement under concurrent load behind the actual server configuration.
